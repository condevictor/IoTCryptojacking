1. BUG IDENTIFICADO
-------------------------------------------------------------
A função subsample_balanced() nas versões anteriores de
zeroday_rf.py e comparacoes relacionadas nao garantia 1:1
quando uma das classes tinha menos amostras que MAX_PER_CLASS:
    pos_s = min(max_per_class, len(pos))   # 35.984
    neg_s = min(max_per_class, len(neg))   # 318.276
Resultado: para o holdout MinerGate (malicious_train=35.984),
o treino ficou 11:1 imbalanced, apesar do nome "balanced".

2. EFEITO DO BUG
-------------------------------------------------------------
RF com 500k/classe (job 32091):
    MinerGate held-out: acc_mal = 0,555
RF v2 com 50 features enriquecidas (ratios_dup3, mesmo bug):
    MinerGate held-out: acc_mal = 0,580
RF com 10k/classe BALANCEADO (job 32143):
    MinerGate held-out: acc_mal = 0,957
    --> o bug custou ~40 p.p. ao RF; as features extras so
        recuperaram ~2,5 p.p. enquanto o bug persistia.
